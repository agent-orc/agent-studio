Recommendation

Keep only per-CLI weekly and current-session percentages, plus today's USD cost, in the desktop usage strip. Put that strip inside the existing header as its second row. On phone, preserve only the primary CLI weekly percentage and today's cost. CLI chips open their quota and model detail; cost opens ledger detail.

The five operator decisions dated 25 September 2026 are settled. Slot counters, weekly cost, active-run spend and model names move into the expanded view. There is no global model chip: concurrent runs can use different effective routes. The slot chip remains a compact component inside the expanded view, resolving the original request for a slot chip without adding another primary number.

Percentages always mean quota used. They are not currency or token share. Preserve source precision to at most one decimal place and retain values above 100%; never clamp the text. Session labels come from the provider; “5H” applies only when it actually reports a five-hour window. The primary CLI follows the current operator CLI selection, then the saved workspace default, then stable provider order. It never changes because another provider spikes in usage. Hidden providers with an acute condition mark the primary trigger with a nonnumeric warning symbol and an accessible explanation.

Data contract

Propose one read-only workspace usage aggregate, GET /api/usage/cockpit, using the existing workspace identity and authorization conventions. This is a proposed endpoint, not an existing route. Extend an equivalent read endpoint if one already owns this projection. Reuse the canonical quota reader, token ledger and run/slot readers. Do not invoke CLI probes per chip or recompute prices in the browser.

AGT-2882 cost boundary: use normalized ledger input. Codex raw input includes cache reads; canonical uncached input is max(0, rawInput - cachedInput), with cached input priced once at its cache-read rate. The UI consumes the resulting ledger USD estimate; it does not subtract cache a second time. Deduplicate historical bus rows and durable task receipts by canonical identity. Expose unresolved legacy normalization as partial coverage. This concept does not claim to verify the deployment of AGT-2882.

Show known USD costs as token-ledger estimates, not provider invoices or subscription charges. Do not infer cost from quota percentage. Round only for display after aggregation: the exact project amounts sum to the workspace total, and rounded rows must reconcile with the displayed total through an explicit rounding remainder when needed. Live run cost is already included when the ledger contains it; the live-spend section is a breakdown, not an increment. Missing live receipts read Pending, never a fabricated zero.

“Today” and “this week” use the workspace's local calendar, never the viewer machine's implicit zone. Use the existing week-start setting, or Monday if no setting exists, and show the boundary. Apply daylight-saving transitions to the UTC query instants. Provider quota windows keep their provider-defined periods; the local calendar controls their displayed reset dates and weekly cost boundaries, not a fictional Monday reset. UTC is available on focus/hover and explicitly in the sheet. Example fixture: Europe/Berlin, 25 September 2026, 16:58; this week is 21–27 September.

Refresh through existing usage events where available, otherwise one shared 30-second request while visible. Pause polling when hidden and refresh on return. Retain the last good value with a stale label until the next successful update. Trust each source's observation timestamp rather than generatedAt. Responses must not mix workspaces after a navigation race.

Popover and sheet

Desktop chips open a nonmodal anchored detail popover with a dialog role and an explicit close control; on phone, the same content uses a modal bottom sheet. The offline mockup uses a modal dialog at all widths for portability; production must implement the desktop popover behavior. Open at the selected CLI or cost section while retaining access to all usage. Use the existing usage/settings hub for the full ledger and CLI management destination, rather than restoring the retired standalone CLI usage surface.

  1. Quota: both windows, exact percentages, reset date/time and countdown, zone and UTC equivalent, last successful fetch and source status.
  2. Cost: today and week totals, configured budget and remaining amount, known/partial coverage, all project rows including unattributed cost, and Open token ledger with workspace and local date filters preserved.
  3. Runs: active runs with provisional spend and timestamps; shared slot chip expands to pool detail.
  4. Models: effective model and reasoning per run, grouped by model within the chosen CLI; model-level quota only when explicitly reported. Do not allocate a CLI quota percentage to models by guessing.
  5. Time: local boundaries plus UTC instants in selectable text. No essential information depends on hover.

Stale / suspiciousMuted last-known value with clock or question mark; detail names the conditionTTL elapsed, probe failure or suspicious snapshot. Do not clear an existing limit based on an untrusted sample.
Unavailable / unsupportedUnavailable or N/A with an accessible reasonChip remains operable. Distinguish no data from real zero; unsupported session quota does not borrow weekly quota.

State precedence is provider limited, budget/confirmed quota alarm, suspicious, stale, loading/unavailable, normal. Keep simultaneous causes in the expanded view. Announce state transitions once per source/window/reset cycle through a polite status region; no live announcement for every numeric tick. Reset alarms only on a trusted recovery or the next confirmed window. An alert may disclose safe routing options but never lower a correctness floor, alter an explicit model pin or automatically move a task.

Keyboard and screen readers

Each chip is one native button, with aria-haspopup="dialog", expanded state and controls relation. Use names such as “Codex, weekly 15 percent used, current five-hour window 32 percent used. Open usage.” Tab follows the visible reading order; hidden chips are removed from the focus order. Enter and Space open. Escape closes and restores the trigger; when the trigger has moved through a breakpoint, return focus to the corresponding visible usage trigger. Desktop popovers allow Tab to leave and close; phone sheets trap focus, make the background inert and retain an explicit Close button. Navigation links use native link semantics and aria-current.

Use a visible two-pixel focus ring and no focus removal. Amounts use tabular figures, while accessible names expand WK, 5H and USD. Status combines wording or shape with color. Tooltip time details appear on keyboard focus as well as hover. Reduced motion disables transitions. In implementation verify 4.5:1 normal text contrast and 3:1 control/focus contrast in both themes; the reconstruction is not an accessibility certification.

Open decisions

No operator choice blocks this concept delivery. The five questions below were answered on 25 September 2026. Human sight review is the next pipeline lane and has not been performed. The descriptor retains decision-pending as required by the concept-delivery contract; that status does not reopen these decisions.

Primary numbers

Decision and recommendation: per CLI weekly and current-session percentage plus today's USD ledger cost. Cost alone hides quota; quota alone hides expenditure. Weekly cost, slot counts and active-run totals remain in detail.

Model scope

Decision and recommendation: per-model breakdown opens from the CLI chip in its popover or sheet. Never show a global model chip in the strip. Any existing composer model selector remains scoped to the conversation it controls.

Phone density

Decision and recommendation: one compact row showing the primary CLI weekly percentage and today's cost; everything else is one tap away in the sheet. No horizontal scrolling or second phone row.

Strip placement

Decision and recommendation: use the second compact row inside the existing desktop header. Collapse into one phone row. Do not add a banner below the header.

Calendar

Decision and recommendation: workspace local calendar for daily and weekly cost windows, local display for quota resets, UTC on hover/focus and in the sheet. Provider periods remain authoritative for quota windows.

Implementation defaults proposed here include an 80% strict quota warning threshold, the 768/1200/1600 CSS px breakpoints, primary-CLI fallback order and shared refresh cadence. Review may refine these details without delaying this completed Dossier.

Implementation

Seven bounded workflow slices are defined in workbench.json with self-contained prompts and acceptance scopes. Promotion creates implementation cards; this delivery does not promote or modify the product.

HUC-S1 · Workspace usage projection

Deliver the read-only data projection and accounting contract in the Dossier Data contract section. Reuse quota, normalized token ledger, active run and slot sources. Propose GET /api/usage/cockpit or extend the existing equivalent owner with normal workspace authorization. Include source freshness/coverage, local day and week UTC boundaries, reset instants, per-project exact totals including unattributed values, route provenance, deduplicated live costs and optional existing budgets. AGT-2882 normalization is a prerequisite: consume normalized uncached input/cacheRead; do not double-subtract cached input or count receipts twice. UI integration is outside this slice.

  • Contract fixtures cover Codex raw input 1000 with 400 cached becoming 600 uncached plus 400 cache-read priced once; already normalized input remains unchanged.
  • Today/week totals equal project children including unattributed and active receipts; duplicate bus/receipt data is counted once, and partial coverage is distinct from zero.
  • Workspace-local day and configurable week boundaries handle midnight, DST and workspace changes; provider reset periods stay intact.
  • Endpoint handles independent source failure and exposes effective route versus configured route. Add focused backend contract tests and document the endpoint.

HUC-S2 · Shared usage chips

After HUC-S1, implement the CLI, cost and expanded-only slot chip components using the central token scale and existing button/popover primitives. Each CLI chip owns its weekly and current-session window as an indivisible unit. Cost uses a USD ledger estimate, not quota conversion. Include normal/loading/unknown/stale/suspicious states and long-number formatting. The slot chip belongs only in expanded usage. Do not integrate responsive shell layout in this slice.

  • Normal chips share baseline, radius and height in light/dark; no gradients, nested mini pills, decorative provider tiles or left accent bars.

  • Values above 100%, long provider names, large USD totals and fractional percentages preserve full numeric units and exact detail values.
  • Focused Playwright component/fixture coverage and screenshots verify both themes, focus and state labels.

HUC-S5 · Usage alarm transitions

After HUC-S1 through HUC-S4, implement the Dossier chip-state matrix. Fresh quota used strictly above 80% warns; explicit provider-limited state takes precedence; configured daily/weekly USD budget exceeded warns on cost. Use existing budget settings; do not invent financial limits or new routing behavior. Unknown/partial data must not claim safety. Surface hidden-provider alarms through a nonnumeric state marker and accessible explanation without adding another primary number.

  • Boundary tests cover 80 versus 80.1, values above 100, absent budget, exact budget equality, daily and weekly overruns, stale and suspicious readings and provider limits at low percentages.
  • Each transition is announced politely once per source/window/reset cycle, not each refresh. Trusted recovery clears state; stale data cannot clear a limit.

  • Playwright screenshots cover quota warning, cost warning, limited, stale, partial and unknown states, including a hidden-provider alarm on phone. Routing and model pins remain unchanged.
