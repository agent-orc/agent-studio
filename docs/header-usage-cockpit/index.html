Header usage cockpit

Quota, cost and live work in one compact strip. A consistent rhythm for the board and task detail beneath it.

Status Decision pendingPhase Decision readyUpdated 25 September 2026
RecommendationUsageResponsive layoutVisual languageEvidence and mockupsOpen decisionsImplementation

The operator asks for usage numbers to take priority, a more compact responsive header, and a visible maturity pass. This Dossier recommends a single usage strip with complete numeric groups, flat navigation, and aligned content below it. It changes no product code.

Delivery path: docs/header-usage-cockpit/index.html. The concept-mode contract requires one new directory under docs/; the requested operations location can be adopted by the platform after review. Existing documentation and the navigation index remain untouched under this task's explicit scope restriction.

Recommendation: B. Use one row from 768 CSS pixels and two rows below it. Treat complete label/value pairs as indivisible units. The decision concerns placement and density, not a new dashboard or a new routing policy.

02 Recommendation

Usage before navigation

Show Claude and Codex with 5-hour and weekly usage percentages, followed by today's and this week's estimated USD cost, then unique active runs and their reported spend. Move secondary navigation before removing usage facts. Keep exact resets, project attribution and accounting evidence one activation away.

This replaces the existing operational strip, even where the shell currently places it at the bottom. The mockups place it at the top in response to the operator's header request. Do not retain a duplicate footer. The top placement and the phone second row are explicit exceptions proposed for human review against the existing edge-navigation and one-line density rules.

Propose GET /api/workspace/usage-cockpit as one cached, authorized read projection. This endpoint is a proposal, not an existing API. Reuse the canonical ledger union and quota/admission snapshots; a header read must not scan the workspace or launch a CLI probe. Use the repository's current server/connector ownership rules during implementation.

Accounting invariant. AGT-2882's canonical normalization already defines Codex input as max(0, rawInput - cachedInput), with cached input priced separately. Consume normalized rows exactly once. For raw input 100,000 and cached input 80,000, ordinary input is 20,000 and cache read is 80,000. At illustrative rates $2/M and $0.20/M, input cost is $0.056, not $0.216. These are arithmetic fixtures, not provider prices. Preserve output/cache-write rates and historical pricing timestamps. Do not subtract cache again in the browser.

Deduplicate live frames and terminal receipts by the canonical usage identity. Replacing a live snapshot with a completion receipt must not double count the same call. Active spend is the reported subset of the ledger, never added to today/week a second time. When a CLI reports usage only after a turn or completion, show the last reported amount and its age; do not interpolate a dollar-per-second estimate.

Calendar recommendation. Use UTC midnight for today and Monday 00:00 UTC for this week, matching the existing UTC week vocabulary. “Last 24 hours” and “last 7 days” are separate ranges and must not masquerade as today/week. Popovers always show UTC; local reset display may be added alongside it with a timezone label. Provider window resets are provider timestamps, independent of ledger calendar boundaries.

Refresh recommendation. Return the last valid snapshot immediately with freshness. Invalidate from the existing events; coalesce visible-tab updates to at most once per 15 seconds with a 30-second poll fallback. Slow to 60 seconds when hidden; refresh on visibility/focus and reconnect. Quota probing stays on its existing provider cadence. Errors preserve the last observation with an age, not a zero. Keep decimal values for sums and round once for display; exact cents and source rows stay in details.

Model scope

Move the current “Defaults for new tasks” selector to the task-creation composer and Settings, reachable through More. In task detail, keep the effective route beside the current run; in chat, the composer selector applies to the next message. The slot popover lists every running route, including a provider fallback. A plural workspace never implies that one header badge controls all active work.

The supplied gpt-6-astra / medium is retained only as an illustrative explicit pin. The routing policy says Astra is not a default tier, and an explicit pin does not establish that it clears a correctness floor. This Dossier neither selects a new default nor recommends a cheaper fallback. Quota and cost must never cross those floors.

Value integrity: never apply ellipsis, clipping or character truncation to numbers, units, model identifiers or reset timestamps. Use tabular figures and nowrap for each label/value pair, not the whole header. At unusual values, localization or 200% zoom, move a whole group to the expanded Usage summary before it overflows. Short money notation such as $12.4k is permitted only as an explicit whole-value abbreviation with the exact amount in the accessible description and popover. Do not round a sub-threshold value to an apparent limit; use one decimal near a threshold. Emergency reflow below 320 effective CSS pixels may exceed the nominal height to preserve access. These are minimum heights, never fixed clipping containers.

Board and detail: the board uses the existing minmax(220px, 1fr) lane contract and 36 px lane headers. On phone, one selected lane occupies the width; an explicit lane selector exposes the others with counts and preserves selection. Tablet may scroll the lane region horizontally, never the entire page or header. Detail moves Result before Overview below 768, with one vertical scroll and the same run selector. Keep the existing task tabs, review actions, drag/drop behavior, pane persistence and model semantics; the mockup omits ancillary tabs to focus on spacing, not to propose their deletion.

Keyboard and assistive technology

Use real buttons for chips with an accessible name that expands W, R, V and A; announce quota as percent used and cost as estimated USD. Use aria-haspopup="dialog", aria-expanded and a labelled dialog. Tab traverses providers, cost, slots, navigation and More in visual order. Enter/Space opens; Escape closes and restores focus to the invoker. Desktop popover focus enters its first meaningful control and can leave normally; mobile modal focus stays inside until closed. Outside click dismisses without changing values. Resizing an open surface preserves its focused item and context.

More uses the standard text-only menu: arrow keys move, Home/End jump, Escape returns focus. Open provider details use dialog semantics, not menu semantics for tabular content. Invisible overflow copies are inert and absent from the accessibility tree. Focus does not jump when values refresh. A single polite live region announces a newly crossed quota/budget/limit state; repeated amounts and every-cent updates remain silent. Retain tooltips on keyboard focus, but do not use them as the only source of a label or reset time. Test reflow at 200% and 400%, reduced motion, touch, and both themes.

04 Open decisions

Recommendations are defaults for review, not recorded approval. No option is preselected and no human sight review is claimed. The Dossier's native decision controls can record the choices before promote-concept.

Primary usage numbers

Recommendation. Keep independent quota percentages and a USD cost chip. A provider quota percent cannot represent monetary cost.

Model scope

Recommendation. Effective models belong beside the current run; next-message choices belong in the composer. More and Settings retain access to defaults for new tasks.

Narrow layout

Recommendation. Use two controlled rows below 768 px so the two primary providers and both cost periods remain visible.

Strip placement

Recommendation. Replace the operational footer with the usage header; do not duplicate it. This is a deliberate amendment to the edge-navigation rule.

Cost calendar

Recommendation. Use UTC calendar day and Monday-start week with explicit boundaries. Retain estimated list-price terminology and optional advisory budgets.

The implementation slice consuming a decision must read the recorded response. If it differs from the recommendation, update its acceptance examples before coding. Until then this remains decision-pending; no implementation cards were created during this concept run.

05 Implementation

Seven bounded workflow slices are defined in workbench.json. Every item has a self-contained prompt and an explicit bounded acceptance scope. Promote them only after the human decisions are recorded. Delivery order: S1 → S2 → S3; S4 follows S1-S3; S5 and S6 follow S3; S7 follows all visual slices.

  1. S1: Expose a cached workspace usage cockpit projection

    The endpoint exposes both quota windows with nullable values, reset timestamps, account scope and distinct unknown/unsupported/limited states; no percent aggregation across accounts.

  2. S2: Integrate usage chips and evidence popovers

    Every configured CLI has both window slots with known, unsupported or unknown values; the two primary CLI groups and separate today/week cost, unique active count and reported live spend render from the API.

  3. S3: Deliver responsive header, overflow and model scope

    At 390, 768 and 1440 px the selected layout shows complete quota windows, both period costs and active spend with no clipped values, overlapped controls or page-level horizontal scroll.

  4. S4: Add advisory usage alarms and telemetry freshness

    Fixtures at 79.9, 80.0, 80.1 and 100 percent and reset-window rollover prove exact threshold and recovery behavior; displayed rounding cannot hide a warning or imply a false limit.

  5. S5: Align board summaries beneath the usage strip

    Seven-item illustrative fixture reconciles all-lane total 7 with lane counts 3, 2, 2; filtered and epic-exclusion cases retain the existing aggregate invariant.

  6. S6: Align task detail costs and contextual model controls

    Pipeline steps, run rows and task totals align under shared token/cost columns and reconcile with the canonical ledger, including partial and zero-cost cases.

  7. S7: Lock the integrated usage and layout visual matrix

    Header, board and detail have light/dark screenshots at 390, 768 and 1440 CSS px with documented data/clock/provenance; 18 integrated normal-state captures and alarm/partial/limit variants are inventoried.

The detailed prompts contain dependencies, exclusions, acceptance criteria and verification. There are no product changes or created implementation cards in this delivery.
