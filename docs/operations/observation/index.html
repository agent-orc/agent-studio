Observation: watcher, telemetry, project feed

Three Dossiers described one stack from three ends: a global Watcher that turns typed failures into cases, an organization-wide telemetry layer that makes raw product signals durable and clusterable, and a project feed that renders what happened as a readable timeline. This Dossier merges them into one theme: how the fleet observes itself, what each layer is allowed to do with what it sees, and which choices are still open.

§3Recommendation

Recommended default

One observation stack with four layers and four separate truths: apps append redacted events to local JSONL files and a collector normalizes them (hybrid transport, option A3); the Agent Message Bus carries the derived, clustered observation; the Watcher correlates observations into durable cases and produces findings, analysis receipts and ticket proposals; the feed and Activity project the same stream for people, agents and stakeholders. Authority stays where it already is: observation never mutates. The Watcher acts only inside the narrow A1 allowlist (option B2), fence salvage stays approval-gated, and the feed is composed deterministically with model prose only in cached batch rollups (option C2).

Model economy

The repository's model routing policy stays authoritative, and cost follows uncertainty only after the correctness floor is met. No model is used for trigger detection, fingerprints, ancestry, counters, thresholds, allowlist checks or idempotency. Bounded compression of oversized evidence uses the cheap route; ambiguous root cause, a repeated grade loop and decision preparation use the strong analysis floor; fencing, lease authority, credible data loss, security and destructive recovery keep the hard floor that quota and price may not lower. Feed rollups are classification and condensation over short text and belong in the cheap batch route, once per day or week, cached as an artefact with its own cost entry.

Privacy posture, carried unchanged from AGT-W38

  • Local first, export never by default. No cloud account, vendor endpoint or internet connection is required.
  • Never collect secrets. Credentials, tokens, cookies, keys and raw authorization failures are rejected or redacted before append.
  • Never collect content by default. Chat messages, prompts, transcripts, audio, document bodies and source contents stay out of the shared payload.
  • Reduce identity. Human actors use rotating app-local pseudonyms unless an audit record needs an authenticated principal.
  • Bound paths and stacks. The bus carries a redacted summary and a reference; the full stack stays in local evidence.
  • Publication is a separate, reviewed delivery action, not a telemetry feature.

What the feed adds on top

The feed is a curation of signals that already exist, not a new producer. It reads task timelines (lane changes, human-review decisions, escalations, integrations, operator requeues), the bus for token and usage figures, Dossier documents as decision events, and now also Watcher findings and telemetry clusters. Three audiences are served by the same list: people see what is happening without reading eighty cards; a task or agent finds the most recent relevant context without scanning the repository; stakeholders receive a daily or weekly summary that is shareable without board access. Token cost is shown beside every entry, per task and per day, which makes the feed a window into the token economy rather than a hidden consumer of it.

The honest gap stays honest: many discussions and decisions still happen in external chats outside the tool, so the feed is only as complete as what reaches the tool. Two non-exclusive remedies exist, and their order is an open decision in §5: make the orchestrator chat the preferred place for decisions, or build a light import for external ones. The feed makes the gap visible either way.
