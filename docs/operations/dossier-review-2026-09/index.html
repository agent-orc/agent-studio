Scope reconciliation

The repository contained 52 Dossiers before this one: 44 under docs/operations, seven under docs/quality, and one at docs/studio-route-ownership. Their lifecycle split was 33 current-list descriptors and 19 History descriptors. Adding this decision-pending review Dossier yields the stated 34 current and 19 History. The matrix therefore reviews all 52 pre-existing Agent Studio Dossiers rather than silently excluding the eight outside docs/operations.

Method

Every index.html was read in full, including alternatives, decisions, implementation logs, evidence, appendices, and later amendments. Each descriptor supplied lifecycle, source cards, related cards, and implementation tasks. Folder-scoped git log --all supplied creation and revision history. Current domain maps and explicit cross-links were used to test whether open choices had moved elsewhere. A missing reference is not treated as evidence of implementation.

No screenshot is included because this Dossier makes no claim about a current visible product surface. Its claims concern repository documents, descriptor metadata, and Git history.

Contradictions

  • Execution environment: W6, W8, W14, and W22 make containers or all-Docker the default; W51's afternoon revision makes reproducible preparation scripts the source of truth and treats Docker as optional isolation.
  • Git ownership: W14 and W22 allow agent-owned pushes; W37, W49, W51, and the current platform contract place integration and remote durability in platform-owned orchestration.
  • Topology: W10, W14, W22, and W25 describe the older three-part topology; W49 introduces the Operations Server as a separate fourth responsibility and supersedes those topology notes.
  • Runner link: W43 assigns the interim link supervisor to the Task Server process; W49 assigns executable operational actions to the Operations Server and keeps W43 only as a bounded migration state.
  • Gate economics: W2 recommends measure-first staging and rejects batching as a default; W36 later recommends one final full-suite batch after cheap checks and model review, based on a different measured saturation regime.
  • Candidate construction: W36 starts from mapped replay into a closed batch candidate; W37 recommends merge-first candidate construction with deterministic fallback. This choice remains unresolved and must be decided once.
  • Retention: W11 proposes a log-specific cap and runner backup; W46 explicitly replaces it with class-based retention, cold archive, full backup, restore, and integrity contracts.
  • Same-day revision: W51's afternoon text explicitly replaces its own morning Docker-mandatory proposal. Only the afternoon revision is current; the morning version remains Git history.
