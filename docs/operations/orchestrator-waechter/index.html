Recommendation

Approve an observe-first global Watcher, then add a narrow autonomous allowlist. Slices 1 and 2 should make incidents durable, visible, and strongly analyzed without mutating task or Git state. Slice 3 may autonomously re-register an unchanged runner and issue a bounded rebase-steer or existing-policy requeue through the application API. §1Mandate

Decision: approval is requested for the architecture, action allowlist, pilot gates, and operating placement. No runtime behavior changes in this dossier.

The Watcher is one global lifecycle coordinator for exception handling. It does not replace the project orchestrators, the runner, the pipeline, or the state machine. It consumes their typed facts and closes the gap between a visible fault and an evidence-backed recovery or decision.

Outcome

Every accepted trigger produces one correlated case that reaches resolved, decision-required, or an explicit bounded gave-up terminal.

Lifecycle authority

The Watcher owns case progression. Existing APIs, attempt fences, pipeline gates, merge queues, and reissue budgets remain the only mutation authorities.

Intelligence boundary

Models summarize and prepare decisions. Pure policy decides whether an action is allowed. A model response never writes task or Git state directly.

Operator promise

The cross-project feed separates an acute problem, a real human decision, work performed, and a finished finding. Raw model chatter is not the product surface.

Operational basis: the manual response recorded in Unverified Deliveries inspected salvage fences, performed card-scoped recovery, analyzed root cause, wrote a dossier, and requeued cards with steer notes. AGT-2543, AGT-2544, and AGT-2545 harden the substrate; this concept adds the reasoning layer above it.

This dossier treats AGT-2543 through AGT-2545 as required upstream contracts and does not assume that every contract is already deployed. Observe-only adapters may consume their final events once available or equivalent existing facts during the pilot.

Case contract

One WatcherCase is keyed by projectId + taskKey + attemptChainId + triggerClass + evidenceFingerprint. At-least-once inputs may reopen or append evidence, but they must not start duplicate model calls or repeat an action. The durable case stores its trigger, current phase, evidence references, action receipts, verification, model route, token use, operator epoch, and terminal reason.

Admission guards

  • Freshness: the task, attempt fence, operator epoch, and Git refs must still match when an action starts and when it commits.
  • Single ownership: one active case lease per task attempt. Project runners may continue normal work, but cannot run a competing recovery action for that attempt.
  • Noise control: retry events with the same evidence fingerprint append to the case. They do not create feed rows or model calls on every sweep.
  • Terminal discipline: an invariant-produced requeue or quarantine is not undone by the Watcher. The case reports it and can add context.

§3Capability ladder

The ladder is sequential and fail-closed. A later stage receives the receipts of every earlier stage. It may stop early when the problem is mechanically resolved.

Inspection package

The deterministic collector builds an immutable, size-bounded WatcherEvidencePack. It records absent evidence explicitly instead of substituting guesses:

  • task.json snapshot, lane, transition history, operator epoch, attempt-chain and current attempt identifiers;
  • typed run outcome, delivery envelope, integration status, grade and aspect findings, reissue and retry budgets;
  • bounded log windows around the trigger, plus full-log content hashes and paths for drill-down;
  • task, runner, fence, and integration refs; baseSha, resultSha, merge base, ancestry verdict, and remote presence;
  • card-scoped diff summary, changed-path inventory, result inventory, gate receipts, and baseline comparison;
  • related-case links and missing-artifact facts, including AGT-2555's generated status.md scaffold distinction.

Analysis receipt

The strong model receives only the evidence pack and a fixed response schema. Its receipt contains competing hypotheses, evidence for and against each, confidence, root cause, affected scope, a recommended recipe or decision, required approvals, verification, rollback, and unknowns. The pure action policy independently evaluates the receipt. Free-form prose cannot grant authority.

The task shows one compact current Watcher panel, not a duplicate transcript: case id, status, last verified finding, current or proposed action, evidence links, and decision owner. Each Watcher transition also appends a structured timeline note through the application API. The panel deep-links to the case and the dossier or postmortem when one exists. Workspace aggregate

The global header shows open problems, decisions required, actions running, and rescues verified in 24 hours. Counts are sums of visible cases and respect project access. Activity retains its project and entry-type filters, with All activity selected by default as established by AGT-2579. Strong-model tokens and historical cost state appear on the analysis row; unknown price is shown as unknown, never zero.

Live delivery

The bus append and the durable WatcherCase transition are the replayable records. AGT-2535's proposed SignalR seam provides the delivery pattern: persist first, publish a project-scoped notification on the existing TaskHub, treat subscriber failure as best-effort, and refresh a complete snapshot after reconnect. Authorized clients join project groups; the workspace feed merges only the groups they may read. A dropped socket cannot lose the incident because the snapshot endpoint rehydrates from the bus projection and case store.

Noise rule

Every state-changing Watcher action is traceable, but identical checks are rollups, not feed rows. A periodic check that finds no new evidence updates counters on the case. It does not create an Observation every five minutes.

§4aEvent-bus substrate

Activity across projects is the chronological view of the central event bus, not a second monitoring system. The Watcher reads typed bus events, correlates them into cases, and writes its own monitoring events back to the same stream.

The Agent Message Bus contract remains the field-level and storage authority. Domain facts still belong to the task state machine, run records, delivery envelopes, integration evidence, and Git. The bus is their append-only, typed communication and observability substrate. Producing a bus event never moves a card or performs a recovery; those mutations continue to use the application authorities in §6.

Every direct trigger in §2 arrives through a durable bus subscription. Producer-owned thresholds stay producer-owned: the Watcher consumes the resulting signal instead of running a competing timer. The five-minute reconciliation sweep remains a bounded backstop for contradictions that no single producer can emit.

Spend controls

  • One strong call per evidence fingerprint. A second call requires materially new evidence or an operator-requested alternative.
  • Batch stale signals into a deterministic project rollup. Do not ask a model to rediscover the same substrate fault for ten cards.
  • Cap concurrent strong analysis globally and serialize it per project. Priority affects waiting time, never the correctness floor.
  • Record selected route, policy version, reason, tokens, quota bucket, price status, and case outcome. Calibrate the estimates after 30 resolved cases per trigger family where volume permits.
  • When the strong route is unavailable, P1/P2 cases wait visibly or ask for an override. They never silently downgrade. P0 cases surface an acute capacity problem.

§6Authority boundary

OwnerResponsibilitiesExplicit non-goals
Mechanical layer
AGT-2543 / 2544 / 2545		 Truthful completion and integration, envelope and fence guarantees, automatic policy requeue, distinct telemetry, stale detection and alarms. It does not infer root cause, compare competing recoveries, or write an operator dossier.
Watcher Correlated incident lifecycle, evidence packaging, exact recipe selection, allowlisted recovery requests, bounded analysis, decision preparation, card and feed reporting. Autonomy classes

  • A0, read-only: inspect, correlate, analyze, and report automatically.
  • A1, reversible and bounded: existing-identity re-registration, precise steer append, and policy-approved requeue through the API. Idempotent receipt and verification required.
  • A2, prepared: fence transplant candidate, clean rebase proposal, or non-trivial retry. The Watcher prepares commands, SHAs, gates, and rollback; a human confirms.
  • A3, human-only: force push, history rewrite, semantic conflict, cross-card scope, failed-gate waiver, permission elevation, protected branch override, or destructive cleanup.

Non-negotiable invariant

The Watcher works on invariant signals. It cannot suppress them, mark a card complete without their proof, or reinterpret missing evidence as success. If its own analysis disagrees with AGT-2543, AGT-2544, or AGT-2545, the result is a visible decision or defect report, not an override.

§7Operating model

Placement

The logical coordinator belongs beside the global Control Plane, not inside the local Studio UI and not inside one project runner. It subscribes to the central event bus, keeps a durable case store, deduplicates globally, and owns one lifecycle lease. Model and repository work is dispatched as bounded, attributable jobs to a runner with a watcher-analysis or read-only evidence capability. Existing pipeline services execute approved mutations. Studio is the persistent status and drill-down surface shown in Mockup B, not the runtime host.

Event-driven loop and reconciliation

  • Immediate from the bus: typed escalations, delivery failures, integration outcomes, and AGT-2545 alerts advance the durable subscription watermark and enter the case inbox.
  • Five minutes: reconciliation joins task lane, attempt, Git integration, fence, runner registration, bus watermark, and open-case state to find silent anomalies. A confirmed contradiction is appended to the bus before case handling continues.
  • Thirty minutes: AGT-2545 owns the accepted-without-integration threshold and repeated warning cadence. The Watcher consumes the emitted fact rather than starting a parallel timer.
  • On every material phase change: the Watcher emits finding-raised, recipe-applied, analysis-complete, or decision-required back to the bus. Identical checks update the case only.
  • Daily: a deterministic bus-and-case rollup reports trigger volume, resolution time, automatic actions, decisions, strong calls, tokens, and unknown-price rows. A model-authored news summary is optional and separately budgeted.

Self-monitoring

An independent health monitor, not the Watcher itself, evaluates the Watcher's one-minute bus heartbeat and subscription watermark. Three missed heartbeats or a five-minute input lag produces a workspace Watcher unavailable Problem in the same bus-backed Activity stream and in system health. The coordinator reports queue depth, oldest unclaimed case, phase age, action retries, dedupe rate, recipe success, human reversals, strong-call latency, tokens, and spend status.

  • Restart replays the durable inbox and resumes cases by idempotency key.
  • An unavailable analyzer pauses only analysis-required cases. Mechanical invariants and normal pipeline recovery continue.
  • An action verification timeout fails closed, publishes the incomplete receipt, and blocks repetition until state is reconciled.
  • Global and per-project concurrency are bounded. There is no nested fan-out and no hidden subagent tree.

Concept contract

  1. Observe pixels after gates. Visual QA does not replace build, test, accessibility, or human product judgment. It catches only clear visible breakage after deterministic evidence exists.
  2. Steer once before exposure. The first clear defect produces one named, evidence-linked correction round. No model output can increase that budget.
  3. Escalate with proof. Exhaustion and unavailable inspection never become acceptance. The Human Gate receives the complete screenshot set and durable receipts.
  4. Promote to a Watcher trigger. W0 should add visual-qa-clear-defect and visual-qa-unavailable trigger schemas keyed by task, review epoch, iteration, and evidence fingerprint. W1 consumes exhausted receipts. W2 reserves strong analysis for contradictory or repeated problem cards.
  5. Measure before widening autonomy. Track false-clear-defect rate, human reversals, retry repair rate, capture availability, tokens, and time-to-human. Route expansion and new defect categories require reviewed evidence, not prompt-only growth.

Reading

Six of eight findings are repetition of an unchanged fingerprint or a contradiction between two sources the server already has. That is exactly the reconciliation sweep of §2, widened from typed failures to "the same thing keeps happening" and "two projections disagree". The Watcher's first job is therefore not intelligence but bookkeeping: fingerprint, count, compare, and stop when the count crosses a threshold.

§10.3 Output: findings become ticket proposals

A finding that survives deduplication and a persistence check (two sweeps) becomes a Watcher case (§4). The new element is the next step: the case produces a ticket proposal, a card draft with the evidence pack inlined in the house prompt style (context with timestamps and file paths, changes, acceptance), a task type, a model recommendation from the routing policy, and the detector class and fingerprint as tags. Proposals reference the case and the cards they overlap; a proposal for a fingerprint that already has an open card is a comment on that card, not a new card.

§10.4 Moderation: contingent and review mode

ControlRule
ContingentA dedicated Watcher budget per day and per week in tokens and in count: model calls (Mini/high for compression, Sol/medium for analysis, §5), proposals created, comments appended. Read from the Token Economy price catalog and shown in Workspace CLI Management next to the quota strips. When the contingent is used up the Watcher keeps detecting and counting but stops calling models and creating proposals; the backlog of unanalysed cases is visible.
Review modeProposals never enter Ready by themselves. They land in a Watcher inbox (a proposal state on the card: 1-preparation with tag watcher-proposal and the case link) and in Activity as a Decision entry. The operator approves (card moves to Ready with the recommended model), edits, merges into an existing card, or rejects with a reason that feeds the detector's suppression list. A class can be promoted to auto-approve only after ten accepted proposals without an edit, and only for hygiene and repetition classes; contradictions and drift stay human-approved.
SuppressionRejected fingerprints are suppressed for a configurable period; suppression is visible and expires. Known-noise sources (planned maintenance windows, deliberately parked cards) are declared, not guessed.
AuditEvery proposal carries the detector rule, fingerprint, evidence pack digest, model calls with cost, and the operator decision. Proposals and their outcomes are the evidence for promoting a class.
