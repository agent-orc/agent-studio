§5Areas and tags

The review's categories are the first draft of something the product lacks: a vocabulary that organises documents and cards beyond the folder tree and the board lanes. Today the workspace has a tag registry with fourteen tags (architecture, performance, quality, ui-ux, security, docs, observability and a few experiments), cards can carry tags, and Dossiers carry a pattern. None of the 862 Agent Studio cards carries a tag. The registry exists; nothing fills it.

Areas. An area is a bounded part of the application with its own terms. The starting set for Agent Studio comes from the review, refined by the domain maps in docs/concepts: execution and runner, delivery chain, gates and review, observation, task and board UI, Dossiers and documentation, websites, security, retention, token economy. Each area owns a glossary page: the terms an agent must use for that area, with one definition each. The glossary is the ubiquitous language; tags are its handles.

Tags. Two kinds. Area tags name the area a document or card belongs to; a card may carry more than one. Facet tags name a cross-cutting aspect: decision, incident, evidence, guideline, migration. Both live in one registry per project with a product default that every project inherits; a project may add its own areas in its project definition.

Auto-tagging. A pipeline step that runs on card creation and on Dossier creation in every project by default: it reads title and body, the registry as a closed list, and the area glossaries as context, and returns area tags plus facet tags with a confidence. Below the confidence threshold it proposes instead of assigns. A backfill job tags the existing cards and Dossiers once. This is classification over a short text with a closed list; a cheap model class is the right tool, with an explicit route in model routing so it never falls to the coding class.

Maintenance. A periodic step reviews tag usage: unused tags are proposed for retirement, frequently co-occurring free terms are proposed as new tags, near-duplicates are proposed for merging, and Dossier decisions and ADRs feed new terms into the area glossary. Proposals go to the operator as decision cards (W54); nothing changes silently.

§7Recommendation

A. Consolidate to the sixteen-Dossier target set through concept cards, one per new theme Dossier, each of which also records its sources as superseded and writes the archive artefacts of its theme. Build the tag system on the existing registry and card tags: add areas with glossaries, Dossier tags in the descriptor, the auto-tagging step as a pipeline default with a cheap-model route, and maintenance proposals as decision cards.

Order. Consolidation first, because the consolidated Dossiers are the best input for the area glossaries. The tag backend can start in parallel; the auto-tagging step and the backfill run once the glossaries exist, so the first automatic tags are already correct.
