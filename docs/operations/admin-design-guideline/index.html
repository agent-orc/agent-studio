Admin Surface Design Guideline

A binding visual and copy standard for dense operator surfaces. Admin pages stay flat, use the available width, expose detail on demand, and present one calm statement for each fact.

Status: living standard Phase: accepted Evidence: operator captures from 9 and 10 August 2026 Scope: guideline and reference, incremental adoption per revamp card
Accepted

This dossier is the default contract for every new or touched admin surface. Existing pages migrate only when their owning card touches them. The standard grows append-only via refresh and revamp cards.

01Decision and rejected alternatives

The standard applies to operational views such as Activity, pipeline and planning status, settings, workbench viewers, notices, diagnostics, and other administrative control surfaces. It does not turn content documents into dashboards.

Selected direction: one flat admin grammar

Hierarchy comes from alignment, spacing, typography, and restrained whole-surface tints. A page is a workspace, not a stack of cards. Stream rows share one grid. Headers summarize one line and disclose detail only when requested.

Alternatives not selected

  • Cards as the default container. Rejected because repeated borders, radii, headings, and inset margins fragment one operational surface into competing boxes.
  • Fix only Activity across projects. Rejected because the same drift appears in planning, pipeline, notice, workbench, and enrichment surfaces.
  • Restyle every admin page at once. Rejected because a large visual migration obscures behavior regressions and creates review scope without product value.

02Binding rules

These rules use MUST and MUST NOT deliberately. Rule identifiers are stable review references.

ADM-01

Flat composition

Admin content MUST remain flat. Do not wrap a section, row group, banner, or status summary in a decorative card, border, radius, or resting shadow. Separate content with spacing, alignment, typography, or a low-contrast tint across the complete surface. Borders remain valid only for controls, focus, resizable shell boundaries, and data structures that require a boundary.

  • Do: render paired outcome facts such as GOAL and WHERE IT STOPPED as sibling rows on the containing surface. Use a calm whole-row semantic tint when the stopped state needs emphasis.
  • Do not: place those rows inside an outer bordered summary box and then wrap the stopped row in a second inset box. Box-in-box outcome summaries create competing boundaries and obscure the information hierarchy.
ADM-02

Full-width notices

An acute notice MUST span the full available content width with no outer margin, rounded corners, floating shadow, or decorative frame. Use one status dot, one short statement, and at most one action. A settled notice becomes quiet or disappears.

ADM-03

One grid for one stream

Every entry type in a stream MUST occupy the same time, identity, type, summary, state, and disclosure columns. Decision, supervisor, gate, runner, task, and system entries may use different whole-row tints, but MUST NOT change width, indentation, or corner geometry. Cross-project Activity is one chronological stream, not project sections.

ADM-04

Compact headers, detail on demand

A normal header or status summary MUST fit one line at desktop widths. Show identity, current state, and the primary action. Put model, session, token, audit, explanation, and other secondary facts behind one accessible disclosure. The narrow layout may wrap to two lines; it MUST NOT become a stack of mini-panels.

ADM-05

One visible statement per fact

Do not restate a fact already visible in the page, filter, lane, row, or action. Counts MUST reconcile with visible children and appear only where they help a decision. A status chip, warning paragraph, and action label MUST NOT all repeat the same outcome.

ADM-06

Sober operational copy

UI copy MUST state the current fact and, when needed, the next action. Do not use narrative paragraphs, quotations, personification, conversational prompts, or speculative explanations in persistent chrome. Put cause, history, and diagnostics in disclosed detail.

ADM-07

Project identity is mark plus short code

Cross-project rows and tabs MUST pair the shared project color mark with the registry shortCode. Color is never the only carrier. Preserve the full project name in an accessible label or tooltip, reuse the shared identity palette, and maintain a contrast ring in both themes.

ADM-08

Operator density, bounded prose

Admin lists default to the existing compact row tokens. Interactive rows keep the 32 px minimum; static rows use the compact 20 px floor. Chrome uses the established 30 px title and tab bars and 28 px pane headers. Streams, tables, and diagrams use the available width. Narrative and Markdown use a 76ch default reading measure, up to 90ch where content benefits. Code blocks scroll internally.

row padding 3px / 6px interactive floor 32px section gap 10px prose 76ch wide prose ceiling 90ch
ADM-09

Theme structure is invariant

Light and dark themes MUST use the same hierarchy, geometry, density, and disclosure behavior. Read semantic --studio-* variables for color and spacing. Do not introduce a one-theme literal. Status tints remain quiet, and motion collapses under reduced-motion preferences.

ADM-10

Fonts are local product assets

Inter and JetBrains Mono MUST be served as versioned local font assets with their license files and font-display: swap. Production surfaces MUST NOT fetch fonts from Google Fonts, another CDN, or a runtime network dependency. System fallbacks remain mandatory. This dossier itself makes no font request.

ADM-11

Side panels are structural layers

A push side panel MUST use its own semantic background level and a neutral hairline or shell elevation at the resizable boundary. This is a shell edge, not a boxed card or a status accent. Its normal header MUST remain one fixed-height row: context type and name take the flexible space, while status, panel access, and Close keep one shared control height. Execution details belong with status, not in the context title. Only the context name and secondary status copy may ellipsize, and their complete values MUST remain accessible. A jump-to-latest control belongs in a reserved transcript-control row immediately above and below the stacking layer of the composer. It MUST never float over message text.

ADM-12

Compact headers protect identity first

A lane or comparable compact header MUST use one UI font family and one vertical centerline. The name is primary at 13 px and 600 weight. Count and operational summary are secondary at 11 px, with tabular figures. The name receives flexible width before trailing decoration. At narrow component widths, summary prose MUST switch to compact notation such as 0/10, with the complete meaning available in an accessible tooltip. Optional decoration collapses next; name ellipsis is the last resort.

ADM-17

Unknown table values stay inline and quiet

A missing metric, release, or activity value MUST render as one muted en dash in the cell. A placeholder MUST NOT reserve the geometry of a meter, progress track, badge, bar, or boxed control. Render data visualizations only when a measured value exists, and preserve the full reason in accessible text when it helps diagnosis.

03Exemplary reference surface

Activity across projects is the canonical admin reference. The two proofs below use one shared geometry and content. Only semantic theme values change.

Page and order

Default filter is All activity. Entries are globally chronological, newest first. Project filters narrow the stream but never regroup it.

Global status

Collapsed: actor, availability, model, boot time, copy action, disclosure. Expanded: scope, last check, and current intervention only.

Entry grid

time | project | type | summary | state | disclosure. The same columns serve every event kind at every density.

Disclosure

Use a native button or details/summary with aria-expanded. Expanded content begins under Summary and remains within the prose measure.

Narrow behavior

Below the grid breakpoint, time, identity, and state remain the first scan line; summary becomes the second. Do not turn rows into bordered cards.

Copy

Use event facts such as “Remote run completed.” Remove greetings, quoted agent voice, speculative help text, and totals visible elsewhere.

State

Acute state uses a whole-row or full-width tint. Historical entries use neutral surfaces. Status never changes entry width.

Typography

UI 12 to 13 px, metadata 11 px, IDs in local JetBrains Mono, all other copy in local Inter with system fallbacks. Numeric columns use tabular figures.

Gaps without cards

  • Self-hosted font packaging. No .woff or .woff2 asset exists under frontend/ in this checkout. The tokens name Inter and JetBrains Mono but depend on installed-font or system fallbacks. There is no dedicated asset, license, and loading card.
  • Full admin inventory. The named screenshot set is fully mapped, but no card owns a systematic audit of every settings, diagnostics, and project administration view. This dossier does not authorize that big-bang sweep.

Evidence boundary

The planning, decision-width, final-verdict, notice, and enrichment evidence includes mocked captures. The screenshot index labels those files accordingly. AGT-2565 also preserves rendered light/dark review captures with unlabeled provenance. The dossier does not relabel mocked evidence as real.

05Adoption and agent contract

Adoption is incremental and reviewable. It does not create a migration program.

01 · READ

Load the hard rules and this dossier before admin UI design or implementation.

02 · TOUCH

Apply ADM-01 through ADM-12 to the new or changed surface and its immediate family.

03 · PROVE

Capture light, dark, wide, narrow, collapsed, and expanded states as applicable.

04 · DEFER

Record unrelated legacy drift as a named finding or card. Do not widen the implementation.

Prompt-known path

Repository and frontend agent instructions link this dossier directly at docs/operations/admin-design-guideline/index.html. The short mandatory baseline remains docs/quality/design/style-guide-hard-rules.md. Agents cite ADM rule IDs in review notes and use Activity across projects as the reference when a local admin pattern is unclear.

Definition of done for a touched admin surface

  1. The view remains full-bleed; prose alone receives a reading-width cap.
  2. No decorative card, frame, left status stripe, or floating notice is introduced.
  3. Repeated facts and narrative chrome are removed within the touched scope.
  4. Rows track stable identity and use the same grid for comparable entries.
  5. Both themes and relevant widths are covered by Playwright and preserved screenshots.
  6. Push-panel boundaries, fixed header geometry, ellipsis behavior, and transcript overlays remain collision-free where applicable.
  7. Any intentional exception names the user need, scope, and review evidence. Existing drift is not precedent.

07Details panel addendum

This append-only record captures the operator decisions proven by AGT-2610 on 11 August 2026. It applies to Dossier details panels and compatible preparation flows.

Navigation and identity

  • Keep one navigation path. A details panel does not repeat an Open in Wiki action when the regular navigation and document title links already provide that path.
  • Keep one stable key. The global viewer header owns the copyable Dossier key. Preparation rows and nested controls do not repeat it.

Preparation draft contract

  • Open locally and immediately. Starting feature preparation reveals editable title and goal fields without waiting for a server mutation.
  • Preserve unfinished work. Title, goal, actor, selected options, comments, and the operation identifier persist for the browser session across panel closure, navigation, and reload.
  • Make persistence legible. A visible draft notice and an explicit discard action accompany every retained draft. Draft state clears only after a successful decision or explicit discard.
  • Keep the mutation sequence coherent. Final creation performs prepare, card creation, and confirm in order. A retained created-card reference prevents an interrupted retry from creating a duplicate card.

Flat surface and contrast contract

  • One panel boundary. The popover supplies the containing surface. Linked-card, decision, and draft regions remain flat and use spacing, separators, or quiet semantic tint instead of a stack of nested boxes.
  • Use semantic foreground and field tokens. Body copy uses the primary foreground, supporting copy uses the muted foreground, and controls use the strong border token against the field surface in both themes.
  • Prove readable controls. Normal field text meets a minimum 4.5:1 contrast ratio in light and dark themes. The same geometry must fit inside the details panel at a desktop viewport without clipping.

Reference tooltip contract

  • Use one shared overlay. Dossier task chips and lane dots use the shared task-reference control and application tooltip overlay. Do not add a component-local absolutely positioned popover for either variant.
  • Keep complete text inside the viewport. The overlay is positioned against the browser viewport, uses a readable maximum width, wraps long titles, and preserves each status line without clipping. The same rule applies in the viewer header, linked-card rows, lists, and Wiki surfaces.

08Navigation citizenship

This append-only chapter responds to the 11 August 2026 operator capture in which Dossiers looked like a foreign object beside Board, Deck, Wiki, and Epics. The design goal is not to make Dossiers invisible. It is to give them the same quiet row grammar as their siblings while preserving the one fact an operator may need before opening the page: how many decisions are waiting.

Icon register

  • Use a document motif. Dossiers are documents with a lifecycle, not a folder type. Use the existing monochrome document outline at the same 12 px size, stroke weight, and muted foreground as Wiki and Epics. Do not give the icon an orange fill or a Dossier-only background tile.
  • Keep disclosure separate from identity. The document icon remains stable when the row opens. The shared chevron occupies the same leading column and uses the same right/down shapes, hit area, muted color, and motion as every other expandable tree entry.
  • Selection belongs to the destination. Opening the Dossiers overview selects the Dossiers row. Opening a Dossier selects that leaf; its parent remains expanded but is not also marked current.

Counter semantics

The trailing number means waiting decisions, not Dossier files, current lifecycle items, or hidden history. It is the sum of openDecisionCount across the currently visible non-history children. The same count must reconcile with the visible child metadata. Zero is omitted.

Use the shared neutral navigation-count treatment in both themes. An active row may invert the count only as part of the shared selection contrast. Orange remains reserved for an invalid Dossier, a load failure, or another actual error class. A waiting decision is a normal workflow state, following AGT-2606.

States and children

Resting and hover

At rest, icon, chevron, and optional count use muted neutral tokens. Hover uses the shared full-row hover fill. It does not recolor only the icon, add an outline, or introduce an orange state.

Active overview

The Dossiers row uses the shared navigation selection background and foreground with aria-current="page". No left status stripe is added.

Active leaf

The selected Dossier leaf owns active treatment. The parent shows only its expanded chevron. This avoids two simultaneous current destinations.

With children

Current Dossiers appear first at one stable nested indent. The document motif stays in the icon column; waiting-decision metadata remains quiet and uses tabular figures.

Zero visible Dossiers

Never render a zero badge. If History may contain entries, retain the Dossiers destination and its disclosure, show a quiet No current Dossiers state on expansion, and keep the existing History toggle closed by default.

Truly empty

When the catalogue can prove that both Current and History are empty, keep Dossiers as a simple overview destination without a chevron or count. The overview owns the explanatory empty state.

Tree excerpt variants

All three variants use the same document icon, chevron column, row geometry, hover surface, active fill, and History convention. Only the waiting-decision signal changes.

10Lane header Dos & Don'ts

This append-only record responds to the 11 August 2026 Post Processing lane capture. It extends the name-first rule established for tree entries in AGT-2642 to every board lane and project through the shared lane-header component.

Do: use one type system

Use the local UI family throughout the header. Render the lane name with the primary size and weight; render counts and active/waiting status with the secondary size and tabular figures.

Don't: mix text registers

Do not combine a sans-serif lane name, a differently sized count, monospace status prose, and serif text icons. Icons may use the canonical icon system or inherit the header family.

Do: share one centerline

Keep avatar, name, count, status, and icon controls in one flex row with vertical centering. A text metric or button box must not create a second baseline.

Don't: protect decoration first

Do not let fixed trailing metadata reduce the lane name to an initial fragment. The name owns flexible width; optional decoration compacts or disappears before identity truncates.

Do: respond to lane width

Use a component container breakpoint. Change 0 active / 10 waiting to 0/10 when the lane is narrow and preserve the full wording in the accessible tooltip.

Don't: wrap the normal header

Do not stack count, status, or controls into another row. Keep the ordinary state on one line; use ellipsis only after compaction and optional-decoration rules have run.

11Panel keyboard containment

This append-only rule records the task-detail and CAC-22 embedding contract. It applies whenever a panel with its own scroll viewport is embedded inside a board, list, tree, or other ancestor that also owns keyboard navigation.

Focused viewport ownership

  • Move focus into opened detail content. Opening a detail panel places focus on its active content viewport. The viewport is keyboard-focusable and exposes a visible focus treatment without adding decorative panel chrome.
  • Keep vertical viewport keys local. A focused panel handles ArrowUp, ArrowDown, PageUp, PageDown, Home, and End against its own scroll owner. Handled events prevent their browser default and stop propagation, including at a scroll boundary.
  • Preserve control semantics. Text inputs, editable content, menus, listboxes, trees, grids, sliders, and spin buttons keep their native arrow behavior. Their vertical arrow events still stop at the panel boundary so an ancestor cannot also navigate.
  • Leave navigation keys with their owner. Board, list, or tree task navigation runs only while focus remains in that navigation surface. Escape and Tab keep their established dismissal and focus-order behavior.
  • Do not rewrite pointer scrolling. Keyboard containment adds no wheel or touch interception. Pointer and touch scrolling continue to use the platform behavior.

12Dossier list addendum

This append-only record captures the list-surface decisions proven by AGT-2606 on 11 August 2026. It applies to central and project-scoped Dossier overviews and to comparable decision inventories.

ADM-13: One Dossier entry is one reading unit

  • Lead with the title. Follow it with one quiet metadata line containing project color mark plus registry short code, lifecycle, date, a decision count only when open, and compact linked-card state.
  • Bound the excerpt. Place one short summary below the metadata and keep it within the narrative reading measure. Do not spread prose across the full operational canvas.
  • Keep rows flat. Use generous vertical rhythm and optional hairline separators between siblings. Do not wrap an entry, section, or History group in a card border, radius, inset frame, or resting shadow.

ADM-14: A pending decision is routine state

  • Use neutral treatment. Decision pending and its open count are metadata, not warning pills. Waiting for an operator decision is part of the normal Dossier lifecycle.
  • Reserve orange for acute conditions. Warning and alarm orange belongs to genuine failures, blocked operation, and acute notices in the AGT-2568 family. It must not make normal decision inventory look broken.

ADM-15: Lifecycle labels and totals reconcile

  • Name the actual lifecycle. Use Decision pending for open choice, Accepted / In progress for a decided Dossier whose consequences remain current, and Documented only in settled history. Do not use vague labels such as Tracking.
  • Count visible groups. Current equals the visible decision-pending, active, and decided rows. History equals the archived and documented rows. Invalid descriptors are an explicit error group and do not inflate either lifecycle total.

ADM-16: References and actions stay subordinate

  • Project linked work compactly. Resolve list references in one batch and render the shared clickable lane-dot microcards in stable key order. Loading and deleted tasks retain a quiet ghost state rather than shifting row geometry.
  • Use one compact action hierarchy. A text link opens the full view. When inline review is available, it may use one compact primary button. Do not place two competing outlined buttons beside every entry.
  • Prove the same grammar everywhere. Central and project-scoped variants share the component and lifecycle projection. Capture light and dark at wide and narrow widths; geometry and semantic emphasis remain invariant.

Evidence: deterministic mocked before and after captures for light and dark themes at wide and narrow widths in the AGT-2606 results.

13Human Review requeue addendum

AGT-2749 (2026-09-06 overload night): thirteen cards parked in Human Review read as broken product when every one was a host or account fault. The failure taxonomy now requeues an infrastructure or quota fault instead of parking it; this addendum applies ADM-06 (sober operational copy) to what the lane and the card header show while that retry budget is being spent.

  • State the class, not a narrative. A card mid-retry shows its failure class (Infrastructure or Quota) and the bounded retry counter (retry 2/3) as one quiet metadata line, not a paragraph explaining what went wrong or apologizing for it.
  • Human Review keeps its meaning. A card visible in Human Review carries a verdict worth an operator's judgment: a real product failure, or a retry budget the taxonomy has exhausted. A card still spending its infrastructure or quota retry budget stays in the auto-review lane; it does not occupy Human Review while the platform is still trying.
  • Escalation names the budget it exhausted. When the retry budget is gone, the escalation reason states the class, the signature, and the ratio spent (Integration recovery stopped after 3/3 infrastructure requeues (git-network-timeout)) — the current fact and the next action (fix the host or the account, then requeue), never a speculative diagnosis.

Evidence: RunFailureClassifierTests, AcceptanceRailPolicyTests, and AcceptanceRailHostedServiceTests pin the classification and requeue behaviour; a Playwright capture of the lane showing class and retry counter lands with the card that applies this addendum's visual surface.
