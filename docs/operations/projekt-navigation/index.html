§1Anlass

Operator-Vorgabe vom 16.10.2026, sinngemäß: Die Projekte brauchen eine neue Hauptstruktur mit Operations und Deploy. Epics haben sich nicht bewährt und können vollständig ausgebaut werden. Die neue Klammer werden die Dossiers. Der Ausbau ist eventuell nicht ganz einfach. So wird auch ein Hauptpunkt frei.

§2Heute

Im Explorer hat jedes Projekt diese Hauptpunkte: Board, Deck, Wiki, Dossiers, Epics und danach die Projekt-Adressen (explorer-workspace-tree.component.html). Das Deck sammelt rund 25 Panels in vier Gruppen (project-shell.config.ts):

GruppePanels
InsightOverview, Project URLs, Deployment, Integration, Git View, Visual Evidence, Drift, Observability, Token Usage, Throughput & cycle time
QualitySecurity, Test Quality, Audits & Checks, Proposals
ContextArchitecture, Project Graph, Wiki, Agent Docs, Prompts
ConfigPipeline, Workflow, Orchestrator, Settings, Workspace Defaults, Project Overrides, Ownership Routing

Deployment, Observability und Pipeline sind einzelne Panels zwischen vielen anderen. Epics sind ein Hauptpunkt, werden aber kaum genutzt: Am 16.10.2026 gab es unter den aktiven Karten eine Epic-Karte und drei Karten mit Epic-Bezug. Im Code erwähnen 61 Frontend- und 58 Backend-Dateien Epics, im Backend vor allem in Runner, Tasks, Supervisor und Projects.

Token Usage und Throughput bleiben im Deck: Sie beschreiben die Arbeit der Agenten, nicht die Anwendung. Projekte ohne Umgebungen zeigen Deploy und Operations mit einer Einladung zum Einrichten statt leerer Ansichten.

§4Dossiers als Klammer

Dossiers erzeugen schon heute Karten (implementationTasks, promote-concept) und kennen verwandte Karten (sourceTaskKeys, relatedTaskKeys). Das wird zur Klammer ausgebaut:

  • Jede Karte kann einem Dossier zugeordnet sein, höchstens einem. Karten aus einem Dossier sind ihm automatisch zugeordnet.
  • Die Dossier-Seite zeigt ihre Karten mit Lane, Stand und Umgebungen sowie den Fortschritt der Umsetzungsschnitte.
  • Das Board gruppiert wahlweise nach Dossier. Das ersetzt die Gruppierung nach Epic.
  • Der Chat eines Dossiers kennt seine Karten. „Was fehlt noch?“ beantwortet er aus den Karten und den offenen Entscheidungen.
  • Auf der Karte zeigt ein Hinweis zum Dossier, aus welchem Abschnitt und welcher Entscheidung sie stammt.

§5Ausbau der Epics

Der Ausbau läuft in drei Schritten, damit nichts halb entfernt stehen bleibt:

  1. Aus der Oberfläche: Hauptpunkt Epics, Gruppierung nach Epic und Epic-Oberfläche im Orchestrator entfallen. Das kommt zusammen mit den neuen Hauptpunkten.
  2. Daten überführen: Die eine Epic-Karte und die Karten mit Epic-Bezug werden einem Dossier zugeordnet oder archiviert (EP-D1). Archivierte Karten behalten ihr Feld nur lesend.
  3. Aus Code und Modell: Karten-Art epic, Feld epicId, Routen, Prompt- und Supervisor-Pfade für Epics, Tests; ein Schutztest verhindert, dass Epics zurückkommen. Für ältere Clients ignoriert die API das Feld noch eine Version lang und meldet es als veraltet.
