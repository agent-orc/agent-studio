Navigation rail style guide

A compact lab for aligning the Workspace Explorer and Deck rails. The goal is one visual grammar: one boundary line, one header rhythm, one row grid, and configurable density without per-surface CSS drift.

One boundary owner

The rail owns the visible border-right. Resize handles are transparent overlays and never paint an idle line.

Header contract

Every rail uses the same 39px header. Context is either inline, a small pill, or hidden by config.

Row grid

Rows share 30px height, 8px root pad, 44px child pad, 14px icon column, and 24px trailing gutter.

Section rhythm

Use a named divider mode instead of ad hoc borders: quiet spacing, soft rules, or full rules.

New project: icon action

Recommended default. The workspace row owns creation via a compact plus action, so navigation stays navigation.

New project: context menu

Best when rename/delete/move also live there. It keeps the rail quiet, but discoverability is lower.

New project: child row

Most visible, but it reads like a real item and repeats once per workspace. I would avoid it.
